# Набор данных и признаки модели

## Формат `verified_dataset.json`

Словарь, ключ -- порядковый номер записи в виде строки:

```json
{
  "1": {
    "name": "Таблица 1",
    "url": "https://example.org/page.html",
    "html_text": "<table>...</table>",
    "verification": "genuine"
  }
}
```

Поле `verification` принимает значения `genuine`, `no genuine` и `None`
(последнее -- запись ещё не размечена вручную).

Текущий состав: 1000 таблиц, из них 46 размечены как подлинные и 954 как
неподлинные. Перекос закономерен: подлинные таблицы в вебе редки, и это надо
учитывать при чтении метрик. Точность и полнота по классу `genuine` куда
показательнее общей доли верных ответов, потому что модель, всегда отвечающая
`no genuine`, получила бы 95,4 % верных ответов, не умея ничего.

Набор собирается утилитой из соседнего репозитория `dataset-tool`: она
извлекает случайную выборку таблиц из веб-архива WARC, после чего разметка
проставляется вручную через веб-интерфейс.

## Признаки

Из каждой таблицы извлекается восемь чисел -- `comparisonML.get_parameters`.

Первые семь -- доли ячеек каждого типа от общего числа ячеек:

| Признак | Тип данных в ячейке |
| --- | --- |
| `numeric` | Число, дата, время, деньги, проценты, размерная величина |
| `string` | Текст |
| `link` | Ссылка |
| `media` | Изображение, видео, звук |
| `form` | Элемент формы: поле ввода, кнопка, список |
| `other` | Содержимое со своей структурой: вложенная таблица, список |
| `no_data` | Пусто либо прочерк, `н/д`, `n/a` |

Доли в сумме дают единицу. Если ячеек нет вовсе, всем признакам
присваивается `-1`.

Восьмой признак, `consistency`, -- результат работы эвристики: `1`, если
`get_genuine` разобрал таблицу, и `-1`, если возбудил исключение.

## Как признаки попадают в модель

`GenuineModelWrapper` использует `consistency` не как обычный признак,
а как переключатель:

* `consistency == -1` -- ответ `no genuine` выдаётся сразу, модель не
  вызывается;
* `consistency == 1` -- решение принимает модель по семи долям типов.

Обучение идёт тоже только на таблицах с `consistency == 1`: модели незачем
учиться на примерах, которые она всё равно никогда не увидит.

Практическое следствие: любое изменение в разборе таблицы меняет
`consistency`, а значит и ответы модели. Поэтому правки эвристики надо
сопровождать сверкой результатов -- см. [regression.md](regression.md).

## Тестовый набор `table_for_test.html`

Отдельно от размеченного набора есть HTML-файл с таблицами, на которых
работают тесты `test_heuristic.py` и `test_pipeline.py`. Сейчас в нём
**79 таблиц**. Перед каждой таблицей верхнего уровня стоит заголовок
`<h1> Таблица # N ...</h1>`, где `N` на единицу больше индекса таблицы
в списке `soup.find_all("table")`: тест `test_17_...` проверяет `tables[16]`.
Вложенные таблицы нумеруются по порядку в документе, их номера указаны
в заголовке внешней таблицы.

| Номера | Сколько | Источник | Что это |
| --- | --- | --- | --- |
| 1--16 | 16 | Исходный набор | Таблицы, составленные под отдельные случаи разбора: многоуровневые заголовки и боковики, перерезы, пустые и разнородные данные, вёрсточные таблицы. № 15 -- склонение причастия «основанный» из Викисловаря, № 16 -- онкологическая статистика 2018 года с разделителями секций |
| 17--20 | 4 | Викисловарь, «Шаблоны словоизменений/Глаголы» | Типы спряжения, чередования согласных, схемы ударения настоящего и прошедшего времени. Все подлинные |
| 21--27 | 7 | Викисловарь, заглавная страница | Таблица-каркас страницы (№ 21) с пятью вложенными блоками (№ 22--26) и таблица родственных проектов (№ 27). Все неподлинные |
| 28--47 | 20 | FanGraphs, главная страница | Меню сайта: результаты матчей (№ 28, вложенные № 29--30) и турнирные таблицы дивизионов (№ 31, вложенные № 32--37), сетки ссылок на команды (№ 38--43), рейтинги WAR (№ 44--47) |
| 48--49 | 2 | FanGraphs, сплиты Eric Stults | Итоги карьеры и данные драфта в виде «ключ -- значение» |
| 50--79 | 30 | FanGraphs, отчёт о травмах | По таблице на каждую команду лиги |

Адреса страниц:

* [Викисловарь: Шаблоны словоизменений/Глаголы](https://ru.wiktionary.org/wiki/Викисловарь:Шаблоны_словоизменений/Глаголы)
* [Викисловарь: Заглавная страница](https://ru.wiktionary.org/wiki/Викисловарь:Заглавная_страница)
* [FanGraphs: главная](https://www.fangraphs.com/)
* [FanGraphs: сплиты Eric Stults](https://www.fangraphs.com/players/eric-stults/8011/splits?position=P)
* [FanGraphs: отчёт о травмах](https://www.fangraphs.com/roster-resource/injury-report)

Таблицы № 17--79 сняты 26 сентября 2026 года.

**Как переносились таблицы.** Викисловарь отдаёт страницы в разметке Parsoid,
и таблицы скопированы из ответа сайта дословно, как строка, без пересборки
через BeautifulSoup. FanGraphs закрыт проверкой Cloudflare, а часть таблиц
строит скриптами, поэтому HTML взят из браузера после загрузки страницы --
в том виде, в каком таблицы видит посетитель. Повторы отброшены: меню сайта
одинаково на всех трёх страницах, а многие таблицы FanGraphs хранятся
в двух одинаковых копиях (для закреплённой шапки и для мобильной вёрстки).

Данные FanGraphs меняются каждый день, так что это снимок на дату выше,
а не копия текущей страницы.

**Разметка «подлинная -- неподлинная».** У каждой неподлинной таблицы
причина указана в заголовке `<h1>` в скобках: «меню», «навигация» и т. п.
Для FanGraphs вёрсткой считаются меню сайта вместе со списками матчей в нём
(№ 28--30, 31), сетки ссылок на команды (№ 38--43) и рейтинги WAR на главной
(№ 44--47): это блоки-анонсы, которые ведут на полный рейтинг. Подлинные --
турнирные таблицы дивизионов (№ 32--37), карточки «ключ -- значение»
(№ 48--49) и отчёт о травмах (№ 50--79).

**Что исключено.** Таблица сплитов по сезонам со страницы Eric Stults в набор
не вошла. В ней несколько секций, и каждая начинается своей строкой заголовков
посреди данных. Такую структуру эвристика пока не разбирает.
Расписание чатов с главной страницы FanGraphs тоже исключено из набора.

## Формат модели

`trained_model.pkl` хранит объект `GenuineModelWrapper` целиком: внутри
случайный лес и кодировщик меток. Сохранение выполнено через `joblib`,
поэтому в файле записан путь к классу -- `comparisonML.GenuineModelWrapper`.
Переименование модуля `comparisonML` сделает сохранённую модель незагружаемой.
