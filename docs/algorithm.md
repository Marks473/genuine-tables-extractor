# Эвристический разбор структуры таблицы

## Что считается подлинной таблицей

Подлинная таблица -- та, что хранит данные: каждая строка является записью,
каждый столбец -- признаком, типы данных внутри столбца согласованы.
Неподлинная таблица используется для вёрстки: у неё нет устойчивой сетки,
в одном столбце соседствуют разнородные значения, много пустых ячеек.

Проверка строится на одном наблюдении: у таблицы данных строки образуют
правильное разбиение. Каждая следующая строка либо повторяет разбиение
предыдущей, либо дробит её ячейки, но никогда не пересекает их границы.
Именно это свойство и проверяется.

## Точка входа

`get_genuine(table)` пробует разобрать таблицу дважды:

1. как таблицу с заголовком сверху;
2. если не вышло -- как таблицу с заголовком слева, для чего таблица
   транспонируется.

Если ни одна ориентация не подошла, возбуждается ошибка первой попытки.
Перед разбором отсекаются вырожденные размеры: таблица из одной строки,
одного столбца или из двух ячеек данными быть не может.

`is_genuine(table)` -- та же проверка, но возвращает `True` или `False`
вместо исключения.

## Три стадии разбора

Разбор ведёт `vertical_check`, последовательно вызывая три стадии. Каждая
опирается на разметку, проставленную предыдущей.

### Стадия 1: `get_head` -- заголовки

Первая строка объявляется родительской, её ячейки помечаются как `CELL_TITLE`.
Далее для каждой следующей строки ячейки сопоставляются с родительскими:

* сумма ширин потомков **меньше** ширины родителя -- разбор продолжается,
  ячейка остаётся заголовком;
* сумма **совпала** с шириной родителя -- родитель закрыт, переходим к следующему;
* один родитель покрыт одним потомком, и это первая ячейка строки -- заголовки
  закончились, строка является первой строкой данных. Остальные ячейки строки
  проверяются на соответствие родителям, и разбор заголовков завершается;
* сумма **превысила** ширину родителя -- геометрия нарушена, `LayoutError`.

Ячейки с `rowspan`, продолжающиеся на следующую строку, переносятся в набор
родителей без изменений.

Заголовок обязан быть текстом: допустимы типы `STRING`, `LINK` и `GENUINE`.
Картинка или форма в заголовке дают `TitleTypeError`.

**Разделитель секции.** Строка из одной ячейки во всю ширину таблицы
подписывает идущую ниже группу строк, а не описывает столбцы. Такая строка
пропускается при сопоставлении и не расходует ряды родительских ячеек.
Типичный пример -- подзаголовок `Skin` посреди таблицы онкологической
статистики, за которым идут строки по отдельным видам заболевания.

### Стадия 2: `get_data` -- область данных

От первой строки данных проверяется, что сетка держится до конца таблицы.
Требование строже, чем у заголовков: у родительской ячейки должен быть ровно
один потомок той же ширины. Дополнительно сверяются типы данных в столбце --
несовместимость даёт `DataTypeError`.

Из этого правила есть два исключения.

**Перерез (итоговая строка).** Потомок шире родителя. Строка признаётся
итоговой, если в ней ровно одна текстовая ячейка, остальные пусты или содержат
числа, ширина строки равна ширине таблицы, а выше уже встречались данные.
Ячейки такой строки помечаются как `CELL_RESULT`, а структура столбцов
не меняется: следующая строка сверяется с той, что была до переза.

**Объединение боковика.** Потомок шире родителя, но строка на перерез
не похожа. Тогда проверяется, не покрывает ли одна ячейка нескольких
родителей подряд. Так ведёт себя боковик переменной глубины: в таблице
склонения падеж `В.` делится на `одуш.` и `неодуш.`, а следующий падеж `Тв.`
снова занимает обе колонки боковика. Объединение допускается только в первой
ячейке строки и только если оно не покрывает всех родителей -- строка во всю
ширину является перерезом, а не боковиком.

### Стадия 3: `get_sidebar` -- боковик

Запускается, если строк больше двух. Проверяет, что боковики не «зубчатые»,
то есть заканчиваются на одной линии, и помечает их как `CELL_SIDEBAR`.

## Классы ячеек

| Класс | Смысл |
| --- | --- |
| `CELL_TITLE` | Заголовок столбца или подзаголовок секции |
| `CELL_SIDEBAR` | Заголовок строки (боковик) |
| `CELL_DATA` | Содержательные данные |
| `CELL_RESULT` | Ячейка итоговой строки (переза) |
| `CELL_NOT_DEFINE` | Класс не назначен |

## Ошибки разбора

| Исключение | Когда возбуждается |
| --- | --- |
| `LayoutError` | Нарушена геометрия: ширины не сходятся, заголовки зубчатые, таблица вырождена |
| `TitleTypeError` | В заголовке недопустимый тип данных |
| `DataTypeError` | Типы данных в столбце не согласуются либо строка не является перерезом |

Тип ошибки сам по себе полезен: по нему видно, какая именно проверка
отбраковала таблицу. При аудите набора данных это позволяет отделить ошибки
разметки от пробелов в правилах.
