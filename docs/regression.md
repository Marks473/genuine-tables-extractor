# Сверка результатов классификации

## Зачем

Эвристика стоит фильтром перед моделью, поэтому незаметная правка в разборе
таблицы меняет итоговое качество классификации. Тесты этого не ловят: они
проверяют полтора десятка эталонных таблиц, а модель обучается на тысяче.

Контрольный срез снимает поведение всего конвейера на размеченном наборе
и позволяет сравнить «до» и «после» поимённо, а не только по итоговым числам.

## Что входит в срез

| Ступень | Что фиксируется |
| --- | --- |
| Эвристика | Вердикт по каждой из 1000 записей: разобрана либо тип и текст ошибки |
| Признаки | Вектор из восьми чисел на запись и контрольная сумма всей матрицы |
| Модель | Предсказание готовой модели из `trained_model.pkl` по каждой записи |
| Перекрёстная проверка | F1 (weighted), F1 (macro) и доля верных ответов при пятикратной стратифицированной проверке |

Модель при снятии среза **не переобучается**: берётся сохранённый файл.
Благодаря этому расхождение в предсказаниях однозначно указывает на изменение
разбора таблицы, а не на случайность обучения.

Время обучения в срез не входит: оно меняется от запуска к запуску и для
сверки бесполезно.

## Порядок

Перед правкой снимается эталон:

```
python tools/regression_check.py --cv --out before.json
```

После правки -- второй срез и сверка:

```
python tools/regression_check.py --cv --out after.json
python tools/compare_snapshots.py before.json after.json
```

Сверка возвращает код 0, если расхождений нет, и 1, если они есть.
Это позволяет встроить её в любой сценарий проверки.

Ключ `--cv` добавляет перекрёстную проверку. Без него срез снимается заметно
быстрее и годится для частых промежуточных сверок; с ним -- воспроизводит
цифры сравнительной таблицы моделей.

## Как читать результат

Расхождения показываются по ступеням и по записям:

```
Ступень 1, эвристика: изменилось записей -- 4 из 1000
    запись 229: LayoutError -> TitleTypeError
```

Смена типа ошибки при сохранении вердикта «отбраковано» на метрики не влияет:
таблица как не проходила проверку, так и не проходит. А вот переход
`genuine -> LayoutError` или обратный сдвигает счётчики и требует объяснения.

При рефакторинге, который не должен менять поведение, допустим ровно один
исход -- «результаты совпадают полностью». Если срез разошёлся, изменение
надо откатить и разобрать, а не исправлять поверх.
